This guide walks through deploying ByteSend using the provided Docker Compose files. For a more complete self-hosting walkthrough including reverse proxy, TLS, and firewall configuration, see the [Self-Hosting Overview](https://docs.bytesend.cloud/self-hosting/overview).

## Prerequisites

- [Docker Engine](https://docs.docker.com/engine/install/) 24+
- [Docker Compose](https://docs.docker.com/compose/) v2 (included with Docker Desktop)
- A domain name pointing to your server (for production)

---

## Option 1: Full Stack with Docker Compose (Recommended)

The `docker-compose.web.yml` file in the repository root starts the ByteSend web application, PostgreSQL, and Redis together.

### 1. Clone the repository

```bash
git clone https://github.com/NodeByteHosting/bytesend.git
cd bytesend
```

### 2. Configure environment variables

```bash
cp .env.example .env
nano .env
```

At minimum, set these variables:

```bash
# Public URL of your deployment
NEXTAUTH_URL=https://your-domain.com

# Generate with: openssl rand -base64 32
NEXTAUTH_SECRET=your-secret-here

# Postgres — matches the compose service
DATABASE_URL=postgresql://bytesend:changeme@postgres:5432/bytesend

# Redis — matches the compose service
REDIS_URL=redis://redis:6379

# AWS SES credentials
AWS_ACCESS_KEY=your-access-key-id
AWS_SECRET_KEY=your-secret-access-key
AWS_DEFAULT_REGION=eu-west-1
```

### 3. Start the stack

```bash
docker compose -f docker-compose.web.yml up -d
```

### 4. Run database migrations

```bash
docker compose -f docker-compose.web.yml exec web pnpm db:migrate-deploy
```

### 5. Access the app

Open **http://localhost:3000** (or your domain if behind a reverse proxy).

## Option 2: SMTP Server

ByteSend includes a standalone SMTP relay server that forwards SMTP connections to the ByteSend API. It is deployed separately using `docker-compose.smtp.yml`.

```bash
docker compose -f docker-compose.smtp.yml up -d
```

See the [SMTP Server guide](https://docs.bytesend.cloud/self-hosting/smtp-server) for full configuration details including TLS setup.

## Managing the Stack

### View logs

```bash
docker compose -f docker-compose.web.yml logs -f web
```

### Stop the stack

```bash
docker compose -f docker-compose.web.yml down
```

### Stop and remove volumes (destroys database data)

```bash
docker compose -f docker-compose.web.yml down -v
```

### Rebuild after a code change

```bash
docker compose -f docker-compose.web.yml up -d --build
```

## Environment Variable Reference

| Variable | Required | Description |
|---|---|---|
| `NEXTAUTH_URL` | Yes | Public URL of the app |
| `NEXTAUTH_SECRET` | Yes | Random secret for session signing |
| `DATABASE_URL` | Yes | PostgreSQL connection string |
| `REDIS_URL` | Yes | Redis connection string |
| `AWS_ACCESS_KEY` | Yes | AWS access key ID |
| `AWS_SECRET_KEY` | Yes | AWS secret access key |
| `AWS_DEFAULT_REGION` | Yes | AWS region (e.g. `eu-west-1`) |
| `GITHUB_ID` | No | GitHub OAuth app client ID |
| `GITHUB_SECRET` | No | GitHub OAuth app client secret |
| `STRIPE_SECRET_KEY` | No | Stripe secret key (billing) |
| `STRIPE_WEBHOOK_SECRET` | No | Stripe webhook signing secret |
| `GITLAB_URL` | No | GitLab URL for release tracking |
| `GITLAB_REPO_ID` | No | GitLab repository ID |
| `GITLAB_RELEASE_TOKEN` | No | GitLab API token for releases |
| `GITHUB_RELEASE_TOKEN` | No | GitHub API token for releases |
